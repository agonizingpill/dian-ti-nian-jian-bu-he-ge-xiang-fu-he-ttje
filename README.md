# lift-inspection-review

电梯年检不合格项复核工作台，服务南京景诚特种设备检测团队。应用把电梯档案、逐项检验、整改通知、复检证据和合格证签发串成一条可审计流程。

## 业务范围

- 操作员录入设备与检验项，失败项生成整改通知并预约复检。
- 主管审核复检结果并签发合格证，安全回路与制动器关键项一票否决。
- 复检证据必须使用原检验项编码，照片错配会被后端拒绝。
- worker 使用 `DecisionTreeClassifier(random_state=1066, max_depth=3)` 计算分流结果并导出规则路径。

## 业务核验模块

登录后打开页面右下角的「业务核验」。可从实时业务台账筛选记录、导出所选结果，主管可对当前证据签认并填写说明。

- **年检到期排程** 按年检到期日排序并标出近 30 天到期与逾期资产，供检验员安排路线。
- **关键项整改督办** 聚合关键不合格项及整改资料，未开单、过期或缺复检记录可分别交接。
- **证书有效性对照** 对照证书有效期与资产仍未验证的关键缺陷，保留主管判断依据。

### 二次扩展核验

- **复检影像归属核验** 把复检照片与原不合格项编号逐一对照，识别缺影像和串项证据。
- **复检员同档排班冲突** 按复检员与相同预约时点核对尚未完成的排班，重约或关闭后自动释放冲突。

## 业务处置与验收

- 同档复检改约验收

## 双通道分流复核

「分流复核」工作台把同一份送审数据交给**接单处**（API 进程内即时计算）和**后台**（worker 异步计算）两棵分流树各算一遍，两边**建议与命中分支都对上**才自动出结论。

- **转人工**：两边对不上（建议或命中分支任一不同），或等满 `REVIEW_TIMEOUT_SECONDS`（默认 30 秒）仍有通道没算完。超时转人工会标出缺哪一边（`backend_timeout` / `intake_timeout` / `both_timeout`）。
- **补算收回**：超时转人工后，worker 的补算扫描（空闲每 5 秒）会把缺的结果补上；补算到齐且对上时，还没人接手的人工单自动收回并出结论。
- **先落定者赢**：主管接手与补算收回并发时，按先落定的处理（条件 UPDATE 抢状态）；已被接手后迟到的通道结果标记「迟来建议 · 仅作参考」。
- **幂等**：送审按 `(设备, 幂等键)` 去重，中断重试会补齐缺口而不是重复建单；通道结果按 `(送审单, 通道)` 首写胜出，重复投递、重复入队、重复扫尾都不会重复转人工或重复发结论；接手与人工结论对本人重试幂等返回。
- **工作台**：每行显示接单处/后台各自是否已出结果；分歧单标红「两边分歧」，超时单标出哪边没算完；详情里并排展示两边的建议、命中分支、模型版本。

### 演示剧本

```bash
# 1. 正常一致：提交后几秒内自动出结论（两边 baseline 口径一致）
#    工作台 → 分流复核 → 发起送审，任选设备

# 2. 超时 + 补算收回：暂停 worker 模拟后台通道缺席
docker compose pause worker
#    发起送审 → 30 秒后转人工（标注「后台超时未算完」）
docker compose unpause worker
#    worker 补算对上 → 未接手的人工单被收回，自动出结论

# 3. 接手优先：同样暂停 worker 送审，30 秒内主管先「接手」
#    恢复 worker 后补算结果只作参考，主管人工填写结论落定

# 4. 两边分歧：让后台树用严格口径（模拟版本偏斜），健康设备会算出不同建议
TREE_VARIANT=strict docker compose up -d worker
#    对 NJ-XH-118 / NJ-JS-307 发起送审 → 接单处 ready、后台 review → 转人工「两边分歧」

# 5. 幂等：提交中断网/重复点击用同一幂等键重试，不会重复建单；
#    worker 重投结果不会重复发结论
```

### 相关配置

| 环境变量 | 默认 | 说明 |
|---|---|---|
| `REVIEW_TIMEOUT_SECONDS` | 30 | 双通道核对时限，等满即转人工 |
| `INTERNAL_TOKEN` | jc1066-internal | worker 回调内部接口的共享令牌 |
| `TREE_VARIANT` | baseline | 后台树口径，`strict` 用于演示两边分歧 |
